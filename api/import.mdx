The Import API lets you bulk-load flashcards into any Blue Accademy deck from an Anki-compatible tab-separated text export. Instead of creating cards one by one through the Decks API, you can paste or pipe the full text content of an Anki export file and have every card created in a single request. The endpoint reports exactly how many cards were imported and provides per-line error details for any lines it could not parse.

---

## POST /api/v1/import/anki

Import flashcards from Anki's tab-separated export format into an existing deck.

### Request body

<ParamField body="deckId" type="integer" required>
  The ID of the target deck that cards will be imported into. The deck must
  already exist — use [POST /decks](/api/decks#post-decks) to create one first
  if needed.
</ParamField>

<ParamField body="content" type="string" required>
  The raw text content of the Anki export. Each non-comment, non-blank line
  should contain a front and a back separated by the `separator` character.
  Lines starting with `#` and blank lines are automatically skipped.
</ParamField>

<ParamField body="separator" type="string">
  The field separator character used to split each line into a front and a back.
  Defaults to a tab character (`"\t"`) to match Anki's standard export format.
  You can supply any single character if your export uses a different delimiter.
</ParamField>

### Input format

Anki exports each card as a single line where the front text and back text are separated by a tab. Lines beginning with `#` are treated as comments and skipped. Blank lines are also ignored.

```text
# My Kubernetes cards
What is a Pod?	Smallest deployable unit in Kubernetes.
What is a Deployment?	Manages ReplicaSets to ensure desired Pod replicas.
```

<Note>
  The separator must appear **exactly once** per content line. Lines that
  contain no separator or more ambiguous splits are counted as errors and
  reported in `errorDetails`.
</Note>

### Example request

```bash
curl -X POST http://localhost:8000/api/v1/import/anki \
  -H "Content-Type: application/json" \
  -d '{
    "deckId": 1,
    "content": "What is a Pod?\tSmallest deployable unit.\nWhat is a Deployment?\tManages ReplicaSets."
  }'
```

### Response

<ResponseField name="imported" type="integer">
  The number of flashcard lines that were successfully parsed and created in the
  target deck.
</ResponseField>

<ResponseField name="errors" type="integer">
  The number of content lines that could not be parsed. Comment lines and blank
  lines do not count toward this total.
</ResponseField>

<ResponseField name="errorDetails" type="array of strings">
  A list of human-readable descriptions for each parse error. Each entry
  identifies the line number and the reason for failure (e.g. the separator was
  not found). Empty when `errors` is `0`.
</ResponseField>

**Success response — `200 OK`**

All lines parsed and imported without issues:

```json
{
  "imported": 2,
  "errors": 0,
  "errorDetails": []
}
```

**Partial error response — `200 OK`**

Some lines imported successfully while others failed to parse:

```json
{
  "imported": 1,
  "errors": 1,
  "errorDetails": ["Line 3: could not split using separator '\\t'"]
}
```

<Warning>
  A `200 OK` status does not guarantee that every card was imported. Always
  check the `errors` field in the response. When `errors` is greater than `0`,
  review `errorDetails` to identify and fix the problematic lines before
  re-importing.
</Warning>

## Parsing rules

Blue Accademy applies the following rules when processing your import content:

1. **Comment lines** — any line whose first character is `#` is treated as a comment and skipped entirely. No card is created and no error is recorded.
2. **Blank lines** — lines that are empty or contain only whitespace are skipped silently.
3. **Valid card lines** — a line is valid when it contains the separator character and can be split into exactly a front part and a back part. A card is created from each valid line.
4. **Invalid lines** — a line that does not contain the separator is counted as an error. The line number and the separator that was expected are reported in `errorDetails`.

<Tip>
  If you are importing a large deck, run a small test batch of five to ten cards
  first to verify your separator and line endings are correct before sending the
  full export.
</Tip>
