The Cards API gives you fine-grained control over individual flashcards and their spaced-repetition progress. You can submit review ratings, inspect the current scheduler state for any card, undo a mistaken review, edit card content, delete cards permanently, and preview what the next interval would be for each possible rating before committing. All paths below are relative to the base URL `http://localhost:8000/api/v1`.

---

### GET /cards/{card_id}/progress

Retrieve the current spaced-repetition progress record for a card. The progress object contains everything the SM-2-based scheduler needs to calculate the next review time — ease factor, interval, repetition count, and more.

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard.
</ParamField>

```bash
curl http://localhost:8000/api/v1/cards/101/progress
```

**Response — `200 OK`**

```json
{
  "id": 55,
  "cardId": 101,
  "stored_review_interval": 3,
  "easeFactor": 2.5,
  "repetitions": 4,
  "nextReview": 1718400000000,
  "firstReviewedAt": 1717800000000,
  "state": "review",
  "stepIndex": null,
  "lapseCount": 0,
  "lastRating": 2
}
```

<Note>
  If the card has never been reviewed, this endpoint returns `null`. A `null`
  response means the card is still in the `"new"` state and has no progress
  record yet.
</Note>

<ResponseField name="id" type="integer">
  Unique identifier of the progress record.
</ResponseField>
<ResponseField name="cardId" type="integer">
  ID of the flashcard this progress record belongs to.
</ResponseField>
<ResponseField name="stored_review_interval" type="integer">
  Current review interval in days as stored by the scheduler.
</ResponseField>
<ResponseField name="easeFactor" type="float">
  The ease multiplier used to compute the next interval. Starts at `2.5` and
  adjusts based on rating history.
</ResponseField>
<ResponseField name="repetitions" type="integer">
  Number of times the card has been successfully reviewed without a lapse.
</ResponseField>
<ResponseField name="nextReview" type="integer">
  Unix timestamp in milliseconds for when the card is next due for review.
</ResponseField>
<ResponseField name="firstReviewedAt" type="integer | null">
  Unix timestamp in milliseconds of the very first review. `null` if the card
  has never been reviewed.
</ResponseField>
<ResponseField name="state" type="string">
  Current scheduler state. One of `"new"`, `"learn"`, `"relearn"`, or
  `"review"`.
</ResponseField>
<ResponseField name="stepIndex" type="integer | null">
  The current step within a learn or relearn sequence. `null` when the card is
  in the `"review"` state.
</ResponseField>
<ResponseField name="lapseCount" type="integer">
  Number of times the card has lapsed (been rated Blackout while in the review
  state).
</ResponseField>
<ResponseField name="lastRating" type="integer | null">
  The rating given during the most recent review session. `null` if the card has
  never been reviewed.
</ResponseField>

### POST /cards/{card_id}/review

Submit a review rating for a card. The scheduler updates the card's progress record and returns the new state alongside the previous snapshot (so you can undo the review if needed) and a human-readable string of the next interval.

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard to review.
</ParamField>
<ParamField body="rating" type="integer" required>
  Your recall rating for this review. Accepted values:

  <Expandable title="Rating values">
    | Value | Label    | Meaning                                               |
    | ----- | -------- | ----------------------------------------------------- |
    | `0`   | Blackout | Complete blank — could not recall anything.           |
    | `1`   | Hard     | Recalled with significant difficulty.                 |
    | `2`   | Good     | Recalled correctly with some effort.                  |
    | `3`   | Easy     | Recalled instantly and effortlessly.                  |
  </Expandable>
</ParamField>

```bash
curl -X POST http://localhost:8000/api/v1/cards/101/review \
  -H "Content-Type: application/json" \
  -d '{ "rating": 2 }'
```

**Response — `200 OK`**

```json
{
  "progress": {
    "id": 55,
    "cardId": 101,
    "stored_review_interval": 3,
    "easeFactor": 2.5,
    "repetitions": 5,
    "nextReview": 1718660000000,
    "firstReviewedAt": 1717800000000,
    "state": "review",
    "stepIndex": null,
    "lapseCount": 0,
    "lastRating": 2
  },
  "previousProgress": {
    "id": 55,
    "cardId": 101,
    "stored_review_interval": 2,
    "easeFactor": 2.5,
    "repetitions": 4,
    "nextReview": 1718400000000,
    "firstReviewedAt": 1717800000000,
    "state": "review",
    "stepIndex": null,
    "lapseCount": 0,
    "lastRating": 2
  },
  "nextInterval": "3d"
}
```

<ResponseField name="progress" type="CardProgressRead">
  The updated progress record after applying the rating. Contains the full
  progress object — see [GET /cards/{`card_id`}/progress](#get-cardscard_idprogress)
  for all fields.
</ResponseField>
<ResponseField name="previousProgress" type="CardProgressRead | null">
  A snapshot of the progress record immediately before this review was applied.
  Pass this object to
  [POST /cards/{`card_id`}/restore-progress](#post-cardscard_idrestore-progress)
  to undo the review. `null` if this was the card's first-ever review.
</ResponseField>
<ResponseField name="nextInterval" type="string">
  Human-readable string describing how long until the card is due again, for
  example `"10m"`, `"1d"`, or `"3d"`.
</ResponseField>

### POST /cards/{card_id}/restore-progress

Undo a previous review by restoring a progress snapshot. Pass the `previousProgress` object you received from the review response to roll back the card to exactly the state it was in before that review. Pass `null` to reset the card completely back to "new".

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard whose progress you want to restore.
</ParamField>
<ParamField body="progress" type="CardProgressWrite | null" required>
  The progress snapshot to restore. Use the `previousProgress` value from a
  `POST /review` response to undo that specific review. Pass `null` to reset the
  card to a completely new, never-reviewed state.
</ParamField>

```bash
# Undo a review by passing the previousProgress snapshot
curl -X POST http://localhost:8000/api/v1/cards/101/restore-progress \
  -H "Content-Type: application/json" \
  -d '{
    "progress": {
      "interval": 2,
      "easeFactor": 2.5,
      "repetitions": 4,
      "nextReview": 1718400000000,
      "firstReviewedAt": 1717800000000,
      "state": "review",
      "stepIndex": null,
      "lapseCount": 0,
      "lastRating": 2
    }
  }'

# Reset a card to brand-new
curl -X POST http://localhost:8000/api/v1/cards/101/restore-progress \
  -H "Content-Type: application/json" \
  -d '{ "progress": null }'
```

**Response — `200 OK`**

```json
{
  "progress": {
    "id": 55,
    "cardId": 101,
    "stored_review_interval": 2,
    "easeFactor": 2.5,
    "repetitions": 4,
    "nextReview": 1718400000000,
    "firstReviewedAt": 1717800000000,
    "state": "review",
    "stepIndex": null,
    "lapseCount": 0,
    "lastRating": 2
  }
}
```

<ResponseField name="progress" type="CardProgressRead | null">
  The restored progress record. Returns `null` when you reset the card to new
  (i.e. when you passed `null` as the `progress` input).
</ResponseField>

<Tip>
  The typical undo flow is: store `previousProgress` from the review response in
  your application state, then call `restore-progress` with that value if the
  user clicks an undo button.
</Tip>

### PATCH /cards/{card_id}

Update the content of an existing flashcard. You can change the front, back, and code example. All fields are optional — only the fields you include will be updated.

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard to update.
</ParamField>
<ParamField body="front" type="string">
  New question or prompt text for the front of the card.
</ParamField>
<ParamField body="back" type="string">
  New answer or explanation text for the back of the card.
</ParamField>
<ParamField body="codeExample" type="string | null">
  Updated code snippet. Set to `null` to remove an existing code example.
</ParamField>

```bash
curl -X PATCH http://localhost:8000/api/v1/cards/101 \
  -H "Content-Type: application/json" \
  -d '{
    "front": "Updated question",
    "back": "Updated answer",
    "codeExample": null
  }'
```

**Response — `200 OK`**

```json
{
  "id": 101,
  "deckId": 1,
  "front": "Updated question",
  "back": "Updated answer",
  "codeExample": null,
  "difficulty": "medium",
  "tags": "[]"
}
```

### DELETE /cards/{card_id}

Permanently delete a flashcard. The card's review progress record is also removed. This action cannot be undone.

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard to delete.
</ParamField>

```bash
curl -X DELETE http://localhost:8000/api/v1/cards/101
```

**Response — `200 OK`**

```json
{
  "deleted": true,
  "card": 101
}
```

<ResponseField name="deleted" type="boolean">
  `true` if the card was successfully deleted.
</ResponseField>
<ResponseField name="card" type="integer">
  The ID of the card that was deleted.
</ResponseField>

### GET /cards/{card_id}/preview-intervals

Preview the next review interval for each possible rating without actually submitting a review. The response maps each rating value to a human-readable interval string. This is what the Blue Accademy UI uses to render the interval hint on each rating button before you commit to a choice.

<ParamField path="card_id" type="integer" required>
  The unique identifier of the flashcard to preview.
</ParamField>

```bash
curl http://localhost:8000/api/v1/cards/101/preview-intervals
```

**Response — `200 OK`**

```json
{
  "0": "10m",
  "1": "1d",
  "2": "3d",
  "3": "4d"
}
```

<ResponseField name="0" type="string">
  Interval if you rate the card **Blackout** (complete blank). The card is
  immediately requeued for a short re-learn sequence.
</ResponseField>
<ResponseField name="1" type="string">
  Interval if you rate the card **Hard**. A shorter-than-normal interval is
  applied.
</ResponseField>
<ResponseField name="2" type="string">
  Interval if you rate the card **Good**. The standard calculated interval is
  applied.
</ResponseField>
<ResponseField name="3" type="string">
  Interval if you rate the card **Easy**. A longer interval boosted by the easy
  bonus is applied.
</ResponseField>

<Note>
  Calling this endpoint is read-only — no progress is updated, and the card's
  scheduler state is not changed. You can call it as many times as you like.
</Note>
