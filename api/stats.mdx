The stats endpoints let you retrieve study progress for all your decks or drill down into a single deck. Use the overview endpoint to get a high-level picture of where you stand — total cards, mastery, and what's due today — or query a specific deck's stats to power a focused progress view or a review-session dashboard.

---

## GET /stats

Get overall study statistics aggregated across all your decks.

```bash
curl http://localhost:8000/api/v1/stats
```

### Response fields

<ResponseField name="total_decks" type="integer" required>
  The total number of decks you have created.
</ResponseField>

<ResponseField name="total_cards" type="integer" required>
  The total number of flashcards across all your decks.
</ResponseField>

<ResponseField name="mastered_cards" type="integer" required>
  The number of cards across all decks that are considered mastered — typically cards that have reached a sufficiently high review interval.
</ResponseField>

<ResponseField name="due_cards" type="integer" required>
  The total number of cards currently due for review or learning across all your decks. This is the combined count of all learning, relearning, and review cards that are ready to be studied right now.
</ResponseField>

<ResponseField name="total_exercises" type="integer" required>
  The cumulative number of review exercises recorded across your entire study history.
</ResponseField>

<ResponseField name="completed_exercises" type="integer" required>
  The number of review exercises you have completed. Compare against `total_exercises` to gauge overall study completion.
</ResponseField>

### Example response

```json
{
  "total_decks": 5,
  "total_cards": 210,
  "mastered_cards": 47,
  "due_cards": 18,
  "total_exercises": 340,
  "completed_exercises": 298
}
```

## GET /decks/{deck_id}/stats

Get study statistics for a specific deck, identified by its numeric ID.

```bash
curl http://localhost:8000/api/v1/decks/1/stats
```

### Path parameters

<ParamField path="deck_id" type="integer" required>
  The unique ID of the deck whose stats you want to retrieve.
</ParamField>

### Response fields

<ResponseField name="total" type="integer" required>
  The total number of flashcards in this deck.
</ResponseField>

<ResponseField name="mastered" type="integer" required>
  The number of cards in this deck that have reached a high review interval and are considered mastered.
</ResponseField>

<ResponseField name="available_to_study" type="integer" required>
  The number of cards available to study right now — including new cards within today's limit, learning/relearning cards that are due, and review cards that are due.
</ResponseField>

<ResponseField name="newAvailable" type="integer" required>
  The number of new (never-seen) cards remaining for today in this deck, capped by the `newCardsPerDay` scheduler setting. Once this reaches `0`, no more new cards are introduced until tomorrow.
</ResponseField>

<ResponseField name="learnDue" type="integer" required>
  The number of cards currently in the **Learning** or **Relearning** state that are due to be shown now.
</ResponseField>

<ResponseField name="reviewDue" type="integer" required>
  The number of cards in the long-term **Review** state that are due today.
</ResponseField>

<ResponseField name="seenCount" type="integer" required>
  The total number of cards in this deck that have been seen at least once. A card is counted as seen after its very first review, regardless of the rating given.
</ResponseField>

### Example response

```json
{
  "total": 42,
  "mastered": 8,
  "available_to_study": 15,
  "newAvailable": 10,
  "learnDue": 2,
  "reviewDue": 3,
  "seenCount": 20
}
```

<Tip>
  Use the deck stats endpoint to build a dashboard showing per-deck progress, or poll it after each review submission to update a progress indicator in real time. The `available_to_study` field is especially useful as a single badge count — it tells you exactly how many cards are waiting without requiring any client-side arithmetic.
</Tip>
