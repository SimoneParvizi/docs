This page covers everything you need to run the full Blue Accademy stack on your own machine. You'll find details on prerequisites, the services that make up the architecture, environment variable configuration, database seeding, and how to stop or reset the stack without losing your study data.

## Prerequisites

Make sure your machine meets these requirements before starting:

- **Docker 24 or later** — [Install Docker](https://docs.docker.com/get-docker/)
- **Docker Compose v2** — bundled with Docker Desktop; available separately for Linux via the [Compose plugin](https://docs.docker.com/compose/install/linux/)

## Architecture overview

The Blue Accademy stack runs as three services coordinated by Docker Compose:

| Service | Port | Role |
|---------|------|------|
| `postgres-db` | `5432` | Stores all decks, cards, and review history in a Postgres database |
| `backend-api` | `8000` | FastAPI application that serves the REST API and runs the spaced-repetition scheduler |
| `frontend` | `5173` | React/Vite app that provides the study interface you interact with in the browser |

The backend waits for Postgres to pass its health check before starting, and the frontend waits for the backend to pass its health check before it starts. This ordering ensures the database is ready and seeded before you open the app.

## Setup

<Steps>
  <Step title="Clone the repository">
    Clone the Blue Accademy repository and navigate into the project directory.

    ```bash
    git clone https://github.com/SimoneParvizi/blueaccademy.git
    cd blueaccademy
    ```
  </Step>

  <Step title="Start the stack">
    Build the images and start all three services. The `--build` flag ensures you always use a fresh image based on the current source.

    ```bash
    docker compose -f infra/docker-compose.yml up --build
    ```
  </Step>

  <Step title="Wait for health checks and database seeding">
    Docker Compose runs health checks on each service before the dependent service starts. Watch the log output in your terminal — once the backend is healthy, the database is seeded automatically with the starter decks. When seeding completes, you'll see confirmation in the backend container logs. The frontend container will start immediately after and become available in your browser.
  </Step>

  <Step title="Open the app">
    With all three services running and healthy, open your browser and navigate to:

    ```
    http://localhost:5173
    ```

    Click **Flashcards** in the navigation to reach your deck library and begin studying.
  </Step>
</Steps>

## Environment variables

The backend reads its database connection from a single environment variable:

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | Full connection string used by the FastAPI backend to connect to Postgres |

The default value set in `infra/docker-compose.yml` is:

```bash
DATABASE_URL=postgresql+psycopg://blueaccademy:mypassword@host.docker.internal:5432/blueaccademy
```

The connection string follows the format:

```
postgresql+psycopg://<user>:<password>@<host>:<port>/<dbname>
```

If you change the Postgres credentials in the Compose file, update `DATABASE_URL` to match.

<Warning>
  The default Compose configuration is intended for local development only. The Postgres password is set to a well-known default value (`mypassword`). Change this password before exposing the stack to any shared or external network.
</Warning>

## Stopping and restarting

To stop all running containers without removing your data, use:

```bash
docker compose -f infra/docker-compose.yml down
```

Your study history, decks, and cards persist across `down`/`up` cycles because Postgres stores its data in a volume mounted at `~/postgres/blueaccademy` on your host machine. When you run `up` again, the database is already populated and the seed step skips any content that already exists.

## Resetting to a clean state

If you want to wipe all data and start fresh — for example, to re-run the initial seed from scratch — stop the stack and remove the named volume at the same time:

```bash
docker compose -f infra/docker-compose.yml down -v
```

This removes the Postgres volume along with the containers. The next `up` will re-seed the database from the repo-managed starter content as if it were a first boot.
